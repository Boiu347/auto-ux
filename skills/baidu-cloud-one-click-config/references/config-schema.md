# 配置草案合同

## 核心字段

| 字段 | 要求 |
|---|---|
| `robotName` | 必填；创建新机器人时使用，不用于匹配旧机器人。 |
| `businessGoal` | 说明外呼目的和成功条件。 |
| `openingLine` | 必填；保留换行、标点和变量。 |
| `voice` | 必填；记录平台可选择的发音人标识。 |
| `volume` | 可选；未在需求中出现时不得擅自填默认值。 |
| `script` | 话术节点、转移条件、异常分支和结束条件。 |
| `variables` | 名称、用途、来源与示例；不得混入真实完整号码。 |
| `questionnaire` | 问题、顺序、选项、必填性和回填字段。 |
| `callingPolicy` | 电话类型、主叫线路、时间范围与停止条件。 |

平台实际字段可能变化。浏览器预检后，把不可映射、超长或缺失的字段列为阻塞项，不要截断或猜测。

## 字段状态

- `confirmed`：多个来源一致，或用户已明确选定。
- `conflict`：至少两个来源给出不同值；必须由用户处理。
- `missing`：执行所需但所有来源均未给出。
- `suggested`：Codex 的合理建议，不是需求事实；必须经用户接受才能进入确认草案。

## 草案确认

展示每个字段的值和来源定位。用户确认后，对规范化 JSON 计算 SHA-256，作为 `configVersion` 的本地标识。草案发生任何变化都要生成新哈希，并使后续未使用的确认失效。
