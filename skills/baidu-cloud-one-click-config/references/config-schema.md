# 配置草案合同

## 核心字段

| 字段 | 要求 |
|---|---|
| `robotName` | 必填；创建新机器人时使用，不用于匹配旧机器人。 |
| `role` | 必填；映射快捷机器人话术接口的 `role`。 |
| `audience` | 必填；映射目标用户受众。 |
| `businessGoal` | 必填；映射 `taskAndGoal`，说明外呼目的和成功条件。 |
| `openingLine` | 必填；保留换行、标点和变量。 |
| `voice` | 必填；记录唯一的 `ttsVoiceId`、名称和语速/音量/音调。只有名称时先查询可选项，不得猜 ID。 |
| `asr` | 必填；记录唯一的 `asrModelId` 和名称。 |
| `volume` | 可选；未在需求中出现时不得擅自填默认值。 |
| `script` | 对话规则、示例、背景、风格、静默/回合/挂断策略；映射话术接口。 |
| `advancedSettings` | LLM 预播报、打断、FAQ/文档问答和识别参数；API 必填项缺失时必须由用户确认。 |
| `variables` | 名称、用途、来源与示例；不得混入真实完整号码。 |
| `questionnaire` | 问题、顺序、选项、必填性和回填字段。 |
| `callingPolicy` | 电话类型、主叫线路、时间范围与停止条件。 |

## 挂断与对话控制

- 把积极继续信号、明确结束信号和连续静默分别列出，不得只写模糊的“识别用户意图”。
- “可以、方便、嗯、好”等积极/中性回答必须继续；仅明确拒访、不方便或要求停止可立即结束。
- 当前机器人话语是问题、澄清或追问时，不得同时产生挂断事件。
- `maxCallRounds`、每题澄清次数、开放题追问次数、连续静默次数和总时长分别配置，不能互相替代。
- `delayHangUp` 的 API 单位是毫秒。2 秒写 `2000`，不得写 `2`。
- `hangUpThreshold` 的保守提高只能作为风险建议并由用户确认；平台未暴露分类得分时，不得把阈值写成已证实根因。

平台实际字段可能变化。API 预检后，把不可映射、超长、超范围或缺失的字段列为阻塞项，不要截断、夹取边界或猜测默认值。

## 字段状态

- `confirmed`：多个来源一致，或用户已明确选定。
- `conflict`：至少两个来源给出不同值；必须由用户处理。
- `missing`：执行所需但所有来源均未给出。
- `suggested`：Codex 的合理建议，不是需求事实；必须经用户接受才能进入确认草案。

## 草案确认

展示每个字段的值和来源定位。用户确认后，对规范化 JSON 计算 SHA-256，作为 `configVersion` 的本地标识。草案发生任何变化都要生成新哈希，并使后续未使用的确认失效。
