# 网站联动与自动化运行时

只在网站联动、Mac Agent 安装/升级、Codex 任务投递或生产部署诊断时读取。本文约束的是自动化链路本身，不替代发布机器人、导入号码和开始拨号三个业务确认门。

## 安装与升级

- 网站首次安装命令必须完成官方受管 Codex CLI、Mac Agent 和本 Skill 的安装或复用，并启动 `app-server daemon`；不得把额外的 Codex 安装步骤留给使用人。
- 首次配对和升级命令只能依赖 macOS 自带的 `/bin/sh`、`curl`、`plutil` 等系统工具，不得要求使用人预装 Node.js。安装器必须按 Mac 架构获取固定版本的官方 Node.js 运行时、验证 SHA-256，并把受管 Node 的绝对路径写入 LaunchAgent。
- 首次配对生成设备令牌。后续从同一网站升级 Agent 或 Skill 时必须复用该令牌；只有本机没有配对配置或配置属于其他网站时才重新配对。
- 启用中央登录后，终端 `curl` 不能复用浏览器 Cookie。首次安装必须先通过公开的一次性配对接口换取并本地保存设备令牌，再从设备 Bearer 保护的资产 API 下载安装器、Agent 和 Skill；升级直接复用已有令牌。不得为解决下载问题公开 `/downloads`，也不得把登录页 HTML 当作安装脚本执行。
- 从旧生产 IP 升级时，只允许把已验证设备令牌的 `http://118.196.147.13/auto-ux` 配置迁移到 `https://wowdata.guanghexinzhi.cn/auto-ux`；其他跨站地址变化必须重新配对。
- LaunchAgent 必须写入受管 Codex 可执行文件的绝对路径。已有 daemon 持久管理标记时只执行幂等 `start`，不得在升级时重复 `bootstrap` 并争抢管理锁；首次缺失时允许最多 5 次 `bootstrap` 尝试，再执行 `start`。
- daemon 管理命令必须有超时。若 `start` 因陈旧 PID/控制 socket 缺失而失败，只能在 PID 文件、进程启动时间、受管 Codex 真实路径和 `app-server daemon pid-update-loop` 命令全部匹配时终止失效 updater，再重新 bootstrap；任一身份校验不一致都必须停止，不得按 PID 猜测或广泛杀进程。
- 不得使用剪贴板、AppleScript、模拟按键或辅助功能权限投递任务。这些方式需要额外系统授权，也无法证明任务已进入正确的 Codex 会话。

## Codex 任务投递

- 连接 `codex app-server proxy` 时先完成 HTTP WebSocket 升级，再把 JSON-RPC 放入 WebSocket 文本帧。直接向代理标准输入写 JSONL 不是受支持的真实链路。
- 发布或宣称安装成功前，必须通过已安装 Agent 对真实 daemon 执行只读 `thread/list`，并验证收到有效 JSON-RPC 响应。进程存活、单元测试通过或代理端口存在都不能替代这项检查。
- Agent 每次轮询网站时都必须发送自身版本。服务端应在同一事务中更新该版本与心跳，避免页面同时显示新版本和旧心跳，或反之。
- `CODEX_CLI_NOT_FOUND`、`CODEX_APP_SERVER_TIMEOUT`、`CODEX_APP_SERVER_FAILED` 或 WebSocket 握手失败都表示结构化投递不可用。停止交付并修复链路，不得退回复制提示词或模拟键盘。

## 生产发布

- 构建发布包时显式指定生产主机架构；当前生产为 Linux AMD64，因此镜像或原生包必须以 `linux/amd64` 构建。开发机上的 Apple Silicon ARM64 构建不能直接作为生产候选。
- 使用影子容器或等价候选实例发布：候选实例完成迁移和健康检查后再原子切换流量。不得直接热改正在服务的容器。
- 切换前记录旧 revision 和回滚目标；候选失败时保留当前生产实例，不把部分更新的 Agent、Skill 或静态资源暴露给使用人。

## 网站身份与任务可见性

- 表单草稿和任务历史必须按已验证的用户与工作区保存在服务端，不能以浏览器本地存储冒充跨设备保存。
- Mac 配对令牌只用于设备投递，不能替代网站用户认证。中央登录代理必须先移除客户端传入的身份断言头，再签发项目绑定、短时有效并经过应用验签的断言。
- 中央登录代理只能对健康检查、一次性配对请求，以及携带格式正确的设备或执行 Bearer Token 的机器 API 绕过交互登录；应用必须继续校验令牌哈希、作用域和有效期。不得把整个 `/api` 目录设为公开例外。
- 从旧版配对身份升级时，只能在中央身份已验证、原浏览器配对令牌有效、且旧作用域从未绑定过其他身份的情况下原地认领。否则保持未配对并要求重新配对，不得按“唯一用户”或最近活动记录猜测归属。
- 普通可验证阶段变化使用非阻塞通知；发布、导号、拨号、失败和需要人工处理的状态使用阻塞确认界面。通知只展示网站已经收到的真实事件，不把等待或网络重连推测成进度。

## 端到端验收

依次回读并保存真实证据：

1. 生产容器健康，运行 revision 与目标提交一致。
2. 生产下载资源中的 Agent 和 Skill 与目标版本一致。
3. 本机升级后 `app-server daemon` 和 LaunchAgent 均为运行状态。
4. 数据库中的 Agent 版本与最近心跳来自升级后的真实轮询。
5. 已安装 Agent 通过 daemon proxy 完成真实只读 `thread/list`。

任何一项无法回读时保持未验证状态。写请求结果未知时先查询当前 revision、版本、心跳和运行态；禁止自动重发、补写成功事件或静默切换到浏览器/剪贴板路径。
