# 百度云外呼一键配置平台设计

日期：2026-07-29  
状态：已完成交互确认，等待书面规格复核  
方案：云端控制台 + 本地 Codex 插件

## 1. 背景

团队成员收到调研需求后，需要从飞书研究方案、会议纪要、问卷和本地文件中整理信息，再在百度云客悦中创建并配置外呼机器人。现有人工或临时自动化方式容易出现目标机器人错误、中文乱码、错标签页、重复重试、发布状态误判、号码错误、重复拨号以及接通结果误报。

本项目提供一个多人使用的网站。网站负责资料提交、配置草案、人工确认、实时进度和审计；用户电脑上的 Codex 插件负责读取本地资料及登录态，并实际操作飞书和百度云。

## 2. 目标

- 支持飞书链接、飞书会议纪要、问卷章节、单独问卷链接、上传文件和粘贴文本。
- 从资料生成结构化百度云配置草案，允许用户编辑并确认版本。
- 每个任务只新建独立机器人，绝不直接修改已有机器人。
- 在网站实时显示阶段、当前动作、目标对象、校验证据、错误和下一确认点。
- 支持刷新、断网、浏览器关闭和 Codex 重启后的断点恢复。
- 对发布、导入真实号码、开始拨打分别执行本人确认。
- 支持单号码和批量号码，完整号码默认只保存在用户本机。
- 查询百度云外呼记录，准确区分提交、振铃、接通和失败。

## 3. 非目标

- 修改已有生产机器人。
- 无人确认的自动发布、号码导入或拨打。
- 云端保存完整电话号码、飞书原文或原始问卷文件。
- 自动重试真实电话。
- 管理员审批流和复杂 RBAC。
- 适配百度云客悦以外的外呼平台。
- 后台无人值守自动拉起 Codex。
- CRM、外呼结果分析或问卷分析平台。

## 4. 用户与权限

- 用户通过飞书企业账号登录网站。
- 每位用户独立绑定本地 Codex 插件、飞书登录态、百度云登录态、任务队列和审计记录。
- 任务由创建者本人确认高风险动作，不要求管理员批准。
- 本地插件只能领取与当前 `userId` 和 `workspaceId` 匹配的任务。

## 5. 总体架构

### 5.1 云端控制台

负责：

- 飞书企业登录和用户空间。
- 创建任务并分配 `executionId`。
- 保存结构化配置草案、版本、脱敏号码摘要、步骤状态和审计证据。
- 展示混合进度台。
- 发放发布、号码导入和拨打的一次性确认令牌。
- 通过事件流接收本地执行进度。

### 5.2 本地 Codex 插件

负责：

- 通过“在 Codex 中开始执行”按钮和 `executionId` 领取任务。
- 检查插件版本、飞书 CLI、浏览器能力和登录态。
- 使用飞书 CLI 读取飞书资料，不使用浏览器读取飞书链接。
- 在本地解析文件和完整电话号码。
- 使用百度云浏览器适配器创建、配置、发布和拨测机器人。
- 每一步执行前后校验页面和字段，并向云端上报证据。
- 保存本地检查点和敏感数据。

### 5.3 外部系统

- 飞书：沿用当前用户登录态和文档权限。
- 百度云客悦：沿用当前用户浏览器登录态。
- 本地文件系统：保存原始问卷、号码文件、检查点和完整号码。

## 6. Codex 如何知道该做什么

普通 Codex 不依赖聊天记忆理解流程。插件必须提供：

- 专用 Skill：流程、停止条件、确认点和错误处理规则。
- MCP 工具：任务领取、进度上报、检查点、确认令牌和结果写回。
- 百度云页面适配器：路由、字段语义、页面不变量和结果解析。
- 机器可读执行包：任务版本、当前步骤、允许动作和禁止动作。
- 能力清单与版本协商：不兼容时在执行前阻断。

执行包最少包含：

```json
{
  "executionId": "EX-0082",
  "configVersion": 4,
  "currentStep": "robot.create",
  "targetPolicy": "create_only",
  "approvedActions": ["configure"],
  "blockedActions": ["publish", "import_numbers", "start_dial"]
}
```

第一版由用户点击网站上的“在 Codex 中开始执行”启动 Codex 任务。后台自动接单不在第一版范围内。

## 7. 端到端流程

1. 用户登录网站并创建任务。
2. 用户添加任意数量的飞书链接、问卷章节、上传文件或粘贴文本。
3. 本地插件读取原始资料并生成结构化草案。
4. 网站展示来源、冲突、字段草案和缺失信息。
5. 用户编辑并确认不可变的 `configVersion`。
6. 用户点击“在 Codex 中开始执行”。
7. 插件完成版本、能力、登录态和页面预检。
8. 插件新建机器人并锁定 `agentId + robotId + robotName`。
9. 插件逐字段写入、回读、校验并保存检查点。
10. 插件完成发音人、开场白、音量和试听预检。
11. 网站展示发布前配置总览，用户确认发布。
12. 插件发布并读取平台“发布成功”状态。
13. 用户选择单号码或本地号码文件，插件完成本地解析、去重和格式校验。
14. 网站展示脱敏号码和统计信息，用户确认号码导入。
15. 用户再次确认开始拨打，网站发放一次性拨打令牌。
16. 插件明确选择语音电话、真实电话、主叫号码和测试号码后提交一次。
17. 插件查询外呼记录并上报振铃、接通或失败原因。
18. 网站生成任务报告和审计记录。

## 8. 任务状态与进度

### 8.1 阶段

- 资料解析
- 草案确认
- 环境预检
- 新建机器人
- 字段配置
- 语音预检
- 发布确认
- 发布验证
- 号码确认
- 拨打确认
- 外呼验证
- 完成

### 8.2 步骤状态

- `pending`：等待执行。
- `running`：执行中。
- `waiting_confirmation`：等待本人确认。
- `succeeded`：已完成且证据通过。
- `failed`：失败并附带可验证原因。
- `rolled_back`：已恢复到安全检查点。
- `unknown`：无法证明结果，禁止推测成功。

### 8.3 最小步骤记录

每个步骤保存：

- `executionId`
- `stepId`
- `attempt`
- `status`
- `startedAt`
- `endedAt`
- `inputHash`
- `evidenceRef`
- `errorCode`
- `nextAction`

同一 `stepId + inputHash` 已成功或正在执行时不得再次执行。

### 8.4 混合进度台

左侧展示全流程阶段，右侧展示：

- 当前动作和目标对象。
- 已绑定的 `robotId` 和配置版本。
- 最近一条回读、截图或平台记录。
- 错误事实、系统动作和用户可选操作。
- 最后检查点、插件心跳和下一确认点。

进度只由真实步骤状态计算，不使用与执行状态脱离的动画。

## 9. 中断与恢复

- 低风险步骤从最后一个成功检查点重新读取页面后幂等继续。
- 高风险步骤恢复后回到 `waiting_confirmation`，旧确认令牌立即作废。
- 检测到用户接管浏览器时，立即暂停并释放执行锁。
- 恢复前重新扫描域名、路由、标签页、机器人身份、字段值和发布状态。
- 无法验证状态时设置为 `unknown`，等待用户处理。

## 10. 执行安全防线

### 10.1 Target Guard

新建机器人后保存 `agentId + robotId + robotName`。每次写入前重新核对，任何一项不一致都停止。

### 10.2 Encoding Guard

统一使用 Unicode 写入。每个字段写完立即回读并比较规范化内容和哈希；不一致时恢复字段快照。

### 10.3 Page Guard

每次动作前核对域名、路由、页面标记和机器人身份。禁止复用旧控件位置或旧页面索引。

### 10.4 Mutation Guard

只操作本任务新建机器人。每个阶段保存修改前和修改后快照，失败时仅恢复当前机器人。

### 10.5 Publish Guard

区分草案保存、发布请求和发布成功。没有平台“发布成功”证据时不得进入号码步骤。

### 10.6 Voice Guard

检查发音人、开场白、音量、试听结果。拨测时显式选择语音电话、真实电话和主叫线路，不依赖默认显示值。

### 10.7 Phone Guard

完整号码仅在本地解析。网站展示脱敏值、总数、有效数、无效数和重复数。号码确认与拨打确认分离。

### 10.8 Outcome Guard

拨测弹窗关闭只表示请求可能已发送。最终结果必须来自外呼记录，并区分振铃、接通、无人接听、用户忙和其他原因。

### 10.9 Tool Router

- 飞书链接只使用飞书 CLI。
- 百度云操作只使用百度云浏览器适配器。
- 网站进度和确认只使用任务 API。
- 禁止把飞书链接交给浏览器自动化。

### 10.10 Plugin Session Guard

每个任务生成唯一 `pluginSessionId`。插件已初始化时必须复用，禁止反复安装、初始化或创建多个执行器。

### 10.11 Navigation Guard

浏览器只允许进入 `ky.cloud.baidu.com` 的登记路由。Google、搜索结果、未知域名或缺失协议的 URL 立即触发暂停。禁止在地址栏临时拼接 URL 继续尝试。

### 10.12 Tab Binding Guard

执行开始绑定 `browserWindowId + tabId + route`。不得自行新开标签；标签变化后必须重新确认绑定。

### 10.13 Retry Budget

每一步默认最多尝试两次。第二次失败必须停止；只有错误类型改变或用户明确要求才创建新的尝试。

### 10.14 Action Journal

使用 `executionId + stepId + inputHash` 生成动作指纹。已成功或正在执行的动作不得重复调用；拨打动作额外要求一次性确认令牌。

## 11. 数据边界与隐私

默认仅保存在本机：

- 飞书原文。
- 原始问卷和上传文件。
- 完整电话号码。
- 本地浏览器会话和飞书令牌。

允许保存在云端：

- 结构化配置草案及版本。
- 脱敏号码和统计数量。
- 步骤状态、错误码、时间戳和非敏感证据。
- 用户确认记录和审计摘要。

任何可能包含原文或完整号码的截图在上传前必须裁剪或脱敏。

## 12. 错误处理

- 登录态失效：暂停并提示用户重新登录，不反复请求授权。
- 插件离线或版本过旧：开始前阻断，展示安装或升级方式。
- 文档冲突：在草案页逐项展示来源和冲突，确认前不执行。
- 字段超限：生成草案时提前校验并要求用户调整。
- 页面不兼容：标记适配器版本错误，不进行坐标猜测。
- 用户接管页面：2 秒内暂停，重新绑定后才能继续。
- 语音试听失败：阻断发布。
- 发布失败：不进入号码流程。
- 号码解析异常：显示行号和原因，确认前不得导入。
- 拨打状态未知：禁止再次提交，先查询外呼记录或由用户处理。

## 13. 数据模型

主要实体：

- `User`：飞书身份和组织。
- `Workspace`：团队隔离边界。
- `LocalAgent`：插件实例、版本、能力和心跳。
- `Source`：输入类型、来源标识、哈希和本地引用。
- `ConfigDraft`：结构化配置和版本。
- `Execution`：任务、创建者、当前阶段和执行锁。
- `ExecutionStep`：步骤状态、尝试和证据。
- `RobotBinding`：`agentId`、`robotId` 和名称。
- `Confirmation`：动作类型、版本、过期时间和一次性令牌。
- `PhoneBatch`：本地引用、脱敏摘要和数量统计。
- `AuditEvent`：只追加的操作事实。

## 14. 技术方向

建议首版采用：

- Web：Next.js + TypeScript。
- 数据库：PostgreSQL。
- 数据访问：Prisma。
- 实时进度：Server-Sent Events；需要双向控制时再使用 WebSocket。
- 登录：飞书 OAuth。
- 本地连接：Codex 插件中的 MCP 服务和任务客户端。
- 校验：共享 JSON Schema + Zod。
- 测试：Vitest、Playwright、适配器契约测试和固定回放样本。

技术选型可在实施计划中调整，但状态协议、数据边界和安全防线不得削弱。

## 15. 测试与验收

必须覆盖：

- 飞书 Wiki、Docx、会议纪要、上传文件和粘贴文本。
- 飞书已登录、令牌失效和无权限三种状态。
- 中文标点、换行、数字、英文缩写和超长字段。
- 页面刷新、窗口缩放、错误标签页、Google 搜索页和未知路由。
- 用户并发接管浏览器。
- 插件重复连接、版本不兼容和重复初始化。
- 断网、Codex 重启和任务恢复。
- 发布失败和语音试听失败。
- 单号码、批量号码、重复号码、无效号码和空文件。
- 重复点击确认或拨打。
- 外呼记录中的振铃、接通、无人接听、用户忙和其他原因。

上线门槛：使用固定测试资料连续完成 20 次端到端任务，必须同时满足：

- 0 次修改已有机器人。
- 0 次中文乱码或字段回读不一致。
- 0 次打开非白名单网站后继续操作。
- 0 次重复插件会话、重复写入或重复拨号。
- 100% 高风险动作具备独立本人确认记录。
- 100% 拨测任务从外呼记录获得最终状态或明确标记未知。
