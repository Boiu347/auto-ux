# Mac 本地真实 Codex 一键配置闭环设计

## 1. 目标

将 `Boiu347/auto-ux` 从确定性模拟控制台完善为可在一台 Mac 上验证的真实执行入口。用户在网站填写飞书文档链接、补充需求和本地号码文件路径，点击“一键配置”后，网站创建执行记录、打开 Codex 并把完整执行指令放入 Codex 输入区。用户点击发送后，Codex 调用 `baidu-cloud-one-click-config` Skill，读取飞书资料、操作已登录的百度云 Chrome 会话，并把脱敏进度实时回传网站。

第一版只支持 macOS、本机网站、本机 Codex 和本机 Chrome。Railway 部署、Windows、多用户集中派发和后台无人值守启动不在本阶段范围内。

## 2. 已确认的产品边界

- 用户已经安装 Codex、Codex Chrome 扩展和完整 `baidu-cloud-one-click-config` Skill。
- 飞书资料只由 `lark-cli` 读取，复用当前用户登录态。
- 百度云只通过 Codex 可控制的已登录 Chrome 标签页操作，允许域名固定为 `ky.cloud.baidu.com`。
- 每个执行只新建机器人，不修改、复用或删除已有机器人。
- 发布、导入真实号码、开始真实拨号仍在 Codex 对话中分别确认。
- 网站只展示三个确认门的等待或完成状态，不在真实模式中签发外部动作授权。
- 飞书原文、完整手机号、号码文件内容和百度云会话不上传网站、不进入远端日志。
- 网站实时展示执行阶段、当前动作、脱敏证据、错误与最终平台结果。

## 3. 方案选择

### 3.1 采用：本机启动适配器 + Skill 进度上报

网站继续使用现有 Next.js、PostgreSQL、执行合同、事件持久化和 SSE 进度页。新增本机启动适配器负责在用户点击后创建执行、生成受限执行凭据、复制提示词、激活 Codex 并尝试粘贴。Skill 新增确定性上报脚本，使用受限凭据认领执行、发送心跳和发布脱敏事件。

该方案复用现有控制面，且不把 Codex CLI误当作浏览器执行器。Codex CLI 和 IDE 扩展没有浏览器控制能力，真实百度云操作仍由桌面端 Codex 与 Chrome 扩展完成。

### 3.2 不采用：网站直接调用未公开的 Codex 深链

当前官方资料没有给出可从任意网页创建新 Codex 任务并预填提示词的稳定公共 URL 合同。第一版不编造或依赖未文档化的 `codex://` 参数。

### 3.3 不采用：网站启动 `codex exec`

CLI 可以运行本地命令，但不具备本 Skill 所需的登录态 Chrome 控制能力，因此不能完成真实百度云页面操作。

## 4. 系统结构

```text
本机网站表单
  │
  ├─ 创建 execution + 一次性执行凭据 ──> Next.js API ──> PostgreSQL
  │
  └─ 本机启动适配器 ──> 剪贴板 + 激活 Codex + 尝试粘贴
                                │
                                └─ 用户点击发送
                                      │
                                      v
                         baidu-cloud-one-click-config Skill
                           ├─ lark-cli 读取飞书
                           ├─ Chrome 操作百度云
                           ├─ 本地号码解析与执行状态
                           └─ report_progress.py
                                      │
                                      v
                         认领 / 心跳 / 脱敏事件 API
                                      │
                                      v
                              SSE 实时进度页面
```

## 5. 网站任务入口

首页新增真实任务表单：

- 一个或多个飞书链接；
- 补充需求；
- 本地号码文件绝对路径；
- 可选的机器人名称建议；
- 明确提示三次高风险确认将在 Codex 中发生。

提交时客户端和服务端共同校验：

- 飞书 URL 必须属于支持的文档、Wiki、会议纪要或问卷形态；
- 号码只能填写本地路径，网站不得读取或上传文件内容；
- 不接受聊天中粘贴的完整号码；
- 请求大小有上限；
- 每次提交生成新的 `executionId`，目标策略固定为 `create_only`。

服务端只持久化执行元数据、来源数量、输入哈希和用户提供的非敏感摘要。用于启动 Codex 的完整提示词在本机启动链路中短暂使用，不写入执行事件、应用日志或错误响应。

## 6. Mac 本机启动适配器

新增仅在显式本地模式启用的启动端点。它必须同时满足：

- 服务只监听回环地址；
- 请求来自同源页面并通过现有本地会话校验；
- `NODE_ENV=production` 时无条件关闭；
- 使用固定可执行文件和参数数组，不拼接 shell 命令；
- 提示词通过标准输入交给 `pbcopy`，不出现在进程参数或日志；
- 使用固定 AppleScript 激活 Codex并触发粘贴，不把用户输入插入脚本文本；
- 不自动发送，最终仍由用户点击“发送”。

若 macOS 未授予辅助功能权限或自动粘贴失败，系统保留剪贴板内容、打开 Codex，并在网站明确显示“请按 Command+V 后发送”。失败不得误报为已启动执行。

该适配器只为本机验证服务。未来部署 Railway 时，网页服务器无法直接打开用户 Mac 上的 Codex，必须另行设计本地连接器；本设计不把本机适配器伪装成可直接部署的远端方案。

## 7. 执行凭据与 Agent 绑定

创建执行时生成高熵随机凭据，只保存其哈希。明文只进入本次 Codex 启动提示词。凭据能力限制为：

- 认领指定 `executionId`；
- 为同一执行发送心跳；
- 按执行合同追加脱敏事件；
- 读取该执行的必要恢复信息。

凭据不能读取其他执行、创建执行、访问飞书内容、获取号码或调用网站管理接口。首次认领后绑定 `executionId + agentId + sessionId`；重复会话、过期锁和绑定变化沿用现有控制面拒绝逻辑。

## 8. Skill 更新

在完整 Skill 中增加 `scripts/report_progress.py` 和进度上报引用合同。主流程在下列节点上报：

1. 环境与登录态预检；
2. 飞书来源读取；
3. 配置草案生成与确认；
4. 百度云页面预检；
5. 新建并锁定机器人；
6. 逐字段配置与回读；
7. 等待发布确认及发布验证；
8. 等待导号确认及导入验证；
9. 等待拨号确认及单次提交；
10. 外呼记录查询与最终结果。

上报脚本只接受合同允许的枚举、计数、哈希、脱敏样例、页面身份摘要和平台记录 ID。它拒绝完整号码、飞书正文、Cookie、访问令牌和未定义字段。网络暂时失败时最多按受限退避重试；超过预算则保存本地检查点并在 Codex 中报告“网站进度回传失败”，不得因此重复百度云写操作。

## 9. 确认模型

真实执行以 Skill 的本地三次确认记录为外部动作授权来源。网站是观察面，不是授权面：

- Skill 上报 `waiting_confirmation` 时网站显示等待状态；
- 用户在 Codex 中明确确认单一动作；
- `execution_state.py` 消费一次性本地确认；
- 动作完成并回读后，Skill 上报确认摘要和脱敏证据；
- 网站验证事件顺序、执行绑定和动作枚举，但不生成可触发百度云动作的凭据。

现有网站确认按钮保留给模拟器测试，真实执行页面隐藏这些按钮并提示用户回到 Codex 确认。这样不会出现网站与 Codex 两套授权源互相冲突。

## 10. 数据与日志边界

网站允许保存：

- executionId、用户和工作区边界；
- 阶段、步骤、状态、时间、尝试次数；
- 输入哈希、配置版本、机器人身份摘要；
- 号码总数、有效数、重复数、无效数和脱敏样例；
- 百度云回读结果、外呼记录 ID 和平台状态。

网站禁止保存：

- 飞书正文和问卷原文；
- 完整手机号和号码文件；
- 百度云 Cookie、会话存储、密码或验证码；
- 飞书 access token、refresh token；
- 完整执行凭据。

错误信息先归一化为受控错误码和脱敏摘要，再进入事件与日志。

## 11. 错误与恢复

- Codex 未安装或无法启动：执行保持 `created`，网站显示精确本机错误。
- 自动粘贴失败：提示用户手动粘贴，不创建第二个执行。
- Agent 未认领：页面显示“等待 Codex 发送任务”，不启动模拟器兜底。
- 回传断线：Skill 继续保留本地检查点，恢复后按动作指纹补报，不重复外部动作。
- 页面身份、机器人身份或域名变化：Skill 立即停止并上报阻塞错误。
- 发布、导号或拨号结果未知：保持 `unknown`，先查询真实记录，禁止自动重试拨号。
- 网站刷新或重启：从 PostgreSQL 事件游标恢复 SSE，不重新初始化本地执行。

## 12. 测试与验收

### 自动测试

- 表单校验、敏感字段拒绝和任务包生成单元测试；
- 本机启动适配器的参数、回环限制、生产禁用和失败降级测试；
- 执行凭据哈希、权限范围、认领绑定和过期测试；
- `report_progress.py` 的合同、脱敏、重试预算和幂等测试；
- Skill 本地状态与网站事件状态的映射测试；
- 真实模式隐藏网站确认按钮、SSE 刷新恢复和错误状态端到端测试；
- 保留现有模拟器测试作为无外部副作用的回归套件。

### 人工真实验收

自动测试不能证明百度云线上页面可用。完成代码后必须在用户已登录的 Chrome 中：

1. 只读核对真实路由、页面标记、字段和结果页；
2. 使用专用测试机器人和测试号码；
3. 分别确认发布、导号和拨号；
4. 验证只创建新机器人；
5. 验证字段回读、号码统计和真实呼叫记录；
6. 验证网站没有收到飞书原文或完整号码；
7. 将未识别的线上控件记为阻塞，不通过坐标猜测补齐。

只有这次人工验收通过，才能把飞书文档中的能力边界更新为“Mac 本地真实闭环已验证”。在此之前，文档必须继续说明真实拨号尚未验证。

## 13. Skill 与飞书文档交付

实现和验证完成后：

- 更新 Skill 版本与变更说明；
- 重新生成完整压缩包并计算 SHA-256；
- 校验压缩包内 `SKILL.md`、`references/`、`scripts/` 和 `agents/openai.yaml`；
- 保留现有飞书文档结构；
- 替换附件、SHA-256、安装步骤、网站使用方式、进度回传说明和能力边界；
- 未完成人工真实验收时不得把“代码已接入”写成“真实拨号已验证”。

## 14. 非目标

- Railway 或其他云平台部署；
- Windows 支持；
- 服务器直接保存百度云会话；
- 网站后台无人值守启动用户电脑上的 Codex；
- 网站替代 Codex 完成三个高风险确认；
- 修改已有机器人；
- 在 CI 中执行真实发布、导号或拨号。
